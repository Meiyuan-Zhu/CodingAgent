## 已确认

- Vue 3 前端，Java + Spring Boot 后端，前后端分离。见 [ADR-0001](../decisions/0001-frontend-backend-stack.md)。
- 当前框架基线：Vue 3 + TypeScript + Vite，Java 21 + Maven + Spring Boot 3.5.16。见 [ADR-0003](../decisions/0003-framework-baseline.md)。
- 产品形态：Web 界面作为本地 workspace 工作台，不采用上传文件作为主要工作流；界面方向简洁、清晰、Codex-like。见 [ADR-0004](../decisions/0004-local-workbench-ui.md)；具体三栏 + 底部 terminal 和事件投影层见 [ADR-0024](../decisions/0024-codex-like-workbench-ui-projection.md)。
- Agent 运行协议领域模型已建立。见 [ADR-0005](../decisions/0005-run-protocol-domain.md)。
- Workspace 边界和只读文件工具已建立：相对路径、realpath、敏感路径、UTF-8 和大小限制均有测试。见 [ADR-0006](../decisions/0006-workspace-boundary-read-tools.md)。
- 工具注册表已建立：`list_files`、`read_file`、`search_text` 具备工具定义、参数校验、统一执行入口和失败归一化。见 [ADR-0007](../decisions/0007-tool-registry.md)。
- HTTP run API、SSE 事件流和 mock runner 已建立：前端 Run 按钮可创建任务、订阅事件并展示工具执行结果。见 [ADR-0008](../decisions/0008-run-api-sse-mock-runner.md)。
- Workspace 写入与文本编辑工具已建立：`write_file`、`replace_text`、`edit_file` 具备路径边界、UTF-8/大小限制、hash 冲突检测和注册表接入；`edit_file` 是 `replace_text` 的兼容别名。见 [ADR-0009](../decisions/0009-workspace-write-edit-tools.md)、[ADR-0028](../decisions/0028-tool-observation-schema-and-edit-alias.md)。
- 模型适配边界与响应解析器已建立：runner 通过 `ModelClient` 获取响应，`ModelResponseParser` 校验 JSON 输出并将解析失败归为 `MODEL_PARSE_ERROR`。见 [ADR-0010](../decisions/0010-model-boundary-response-parser.md)。
- 多轮 Agent loop 与运行预算已建立：模型工具调用动作和结果都会回填到下一轮请求，轮次、工具调用数和上下文消息窗口有明确限制；上下文裁剪会保留 system 和初始 user，并避免拆散 assistant tool_calls 与 tool result。真实模型 demo 默认预算和单工具轮次策略见 [ADR-0017](../decisions/0017-real-model-demo-loop-budget.md)，工具动作 transcript 见 [ADR-0019](../decisions/0019-agent-transcript-tool-call-context.md)，配对感知裁剪见 [ADR-0029](../decisions/0029-context-window-tool-pair-trimming.md)。
- Runtime 退出语义已梳理：模型最终回答正常完成；round/tool/token/cancel 等系统限制终止；模型 API/解析/内部异常失败；工具执行失败作为 `success=false` observation 回填给 LLM 继续下一轮。见 [ADR-0027](../decisions/0027-recoverable-tool-failure-observations.md)。
- Failure Recovery 已分类：recoverable tool error 继续 Agent loop；resource/policy termination 结束 run；infrastructure failure 标记 failed。工具失败 JSON 包含 `failureKind=RECOVERABLE_TOOL_ERROR`、`recoverable=true` 和 `recoveryHint`；已验证 `read_file` 文件不存在后继续 `list_files`/`read_file` 恢复。见 [ADR-0030](../decisions/0030-failure-recovery-taxonomy.md)。
- Agent system prompt 已改为简短 operating policy：明确只能通过工具访问文件/命令、修改前检查、聚焦最小编辑、修改后尽量验证、工具失败后恢复、避免重复失败动作和无关探索。见 [ADR-0031](../decisions/0031-agent-operating-policy-system-prompt.md)。
- Tool System observation 已结构化：成功 JSON 包含 `success=true` 和 `message`；失败 JSON 包含 `success=false`、`message`、`toolName`、`errorCode`、`recoverable`、`recoveryHint`、`timedOut` 和 metadata；命令结果包含 exit code、stdout/stderr、截断标记、duration 和 timedOut。见 [ADR-0028](../decisions/0028-tool-observation-schema-and-edit-alias.md)。
- Run 取消、工具超时和后台任务生命周期已建立：后端保留 run task 句柄，支持 cancel endpoint，runner 检查取消状态，工具执行有 timeout；命令工具被中断时会清理可枚举的进程树。见 [ADR-0012](../decisions/0012-run-cancellation-timeout-lifecycle.md)、[ADR-0032](../decisions/0032-command-process-tree-cleanup.md)。
- 审批策略和 diff/变更展示已建立：可变更工具在后端需要审批；写入/替换工具返回 unified diff，前端 Diff 面板可展示。见 [ADR-0013](../decisions/0013-approval-policy-diff-display.md)。
- 完整 approve/reject/resume 工作流已建立：可变更工具会让 run 进入 `WAITING_FOR_APPROVAL`，前端可批准或拒绝；批准后同一 run 恢复执行工具并继续 Agent loop。见 [ADR-0014](../decisions/0014-approval-resume-workflow.md)。
- Agent 文件变更撤销已建立：`write_file`/`replace_text` 成功后以后端私有 journal 记录撤销快照，用户可撤销单次工具变更，撤销前校验当前 hash。见 [ADR-0025](../decisions/0025-agent-change-undo.md)。
- H2 本地持久化已建立：run 状态、事件、pending approval 和 undo snapshot 保存到 `backend/data/` 下的本地 H2 文件数据库；前端启动可加载历史 run。见 [ADR-0026](../decisions/0026-h2-run-persistence.md)。
- OpenAI-compatible 模型适配器已建立：应用默认使用 DeepSeek V4 Flash native tools，并从 `DEEPSEEK_API_KEY` 环境变量读取密钥；Spring Boot 集成测试显式覆盖为 mock，保证本地验证离线稳定；已完成真实只读端到端 run、原生 tool calling 真实只读 run 和原生 tool calling 真实修复闭环；provider 空 content 带提醒单次重试见 [ADR-0018](../decisions/0018-empty-model-content-retry.md)；原生 tool calling 协议见 [ADR-0023](../decisions/0023-native-tool-calling-protocol.md)；默认 provider 切换见 [ADR-0037](../decisions/0037-default-real-model-test-mock-override.md)。
- Provider token-level streaming 已建立：OpenAI-compatible native tools 协议可用 `stream=true` 接收文本 delta，runner 持久化 `MODEL_MESSAGE_DELTA`，前端按 round 拼接实时展示；最终完整消息仍通过 `MODEL_MESSAGE_RECEIVED` 保存。见 [ADR-0033](../decisions/0033-provider-token-streaming.md)。
- 命令参数归一化与空 stream 降级已建立：`run_command` 可兼容模型误发的 JSON-string argv array，但继续拒绝 shell command 字符串；OpenAI-compatible native tools stream 为空时降级为非 streaming native retry；前端命令卡可展示历史 JSON-string argv。见 [ADR-0034](../decisions/0034-command-argument-normalization-and-stream-fallback.md)。
- Runtime 单工具调用强制已建立：模型一次返回多个 tool calls 时，runner 只接收并执行第一个，避免 provider-facing native tools 历史出现多工具 assistant 消息后被 DeepSeek HTTP 400 拒绝。见 [ADR-0035](../decisions/0035-single-tool-call-runtime-enforcement.md)。
- Streaming 传输失败降级已建立：OpenAI-compatible native tools streaming 若遇到 IO 传输异常，会降级为非 streaming native retry；HTTP 400/429 等 provider/protocol 错误仍显式失败。见 [ADR-0036](../decisions/0036-streaming-transport-fallback.md)。
- macOS/Homebrew C++ 编译器环境兼容已建立：`run_command` 的最小环境优先包含 Homebrew LLVM/GCC 路径并保留 `TMPDIR`；普通 `g++`/`gcc` 在存在 Homebrew GCC 时解析为 `/opt/homebrew/bin/g++-15`/`gcc-15`，同时继续避免泄漏 `HOME` 和 API key。
- 默认 `MAX_ROUNDS` 不再作为正常任务的紧限制：默认值从 8 调高到 1000，仅保留极端兜底；正常任务主要由模型 STOP、`MAX_TOOL_CALLS=64`、用户取消和错误恢复/失败分类结束。
- Workspace 命令执行工具已建立：`run_command` 使用 argv 数组而非 shell 字符串，cwd 限制在 workspace 内，输出有截断，执行前需要用户审批；中断/timeout 时按 descendants → parent 做 best-effort 进程树清理。见 [ADR-0016](../decisions/0016-workspace-command-tool.md)、[ADR-0032](../decisions/0032-command-process-tree-cleanup.md)。
- Agent 关键逻辑自行实现，项目不使用 Agent 框架/SDK 或 Spring AI。
- decisions/ 记录决策，memory/ 记录开发状态与文档。见 [ADR-0002](../decisions/0002-development-records.md)。
- 正式截止：北京时间 2026-09-03 00:00；此后不推送新提交。
