## 1. 目标与边界

实现本地运行、单用户使用、有 Web 界面的编程智能体。模型决定下一步操作，自研运行时负责参数校验、权限判断、本地工具执行、结果反馈、上下文管理及停止条件。

产品主线：用户能看清 Agent 读了什么、改了什么、执行了什么，以及哪些结果已经验证。开发主线：每个重要设计能追溯到需求、备选方案、实现、测试和真实提交。

### 已确认的约束

- 个人独立项目；允许 AI 辅助开发，但用户必须理解并负责设计。
- 不包装现成 Agent 产品，不使用任何 Agent 框架或 Agent SDK。
- 允许模型 API 客户端库、兼容网关和原生工具调用；不依赖服务端托管文件或代码执行工具。
- 对话历史、上下文、工具定义及本地执行、输出解析、终止条件、错误处理自行实现。
- Web 界面是用户明确提出的项目要求，纳入必做范围。
- 按用户要求采用前后端分离：独立目录、依赖与启动入口，通过接口通信；可保存在同一个公开仓库。
- 公开仓库须在题目发布后新建；保留完整历史，不重写已推送历史。
- 截止为北京时间 2026-09-03 00:00，之后不再推送新提交。
- 凭据不进入代码、提交历史、README 或视频；泄漏后作废更换。
- 提交姓名命名的 ZIP，内含 1000 汉字以内的 README.txt，以及 2 分钟以内、200 MB 以内的 MP4。仓库地址写入 README.txt。
- 文件没有给出评分权重，也未要求多智能体、RAG、插件平台或云部署。

### 第一版不做

多智能体、向量数据库、复杂长期记忆、MCP/插件市场、账号与多人协作、公网命令执行服务、完整在线 IDE、任意语言与任意平台的兼容承诺。

不做这些功能是项目范围控制，不是题目禁止。已有普通 Web/校验/测试库可以承担基础设施工作；每项依赖都核查其是否侵入 Agent 核心职责。

## 2. 已确定技术栈与其余建议

前端选择：Vue 3。是否搭配 TypeScript 待确认。

后端选择：Java + Spring Boot，自研 Agent Core。用户已明确确认，不再以 Node.js + Fastify 作为业务后端候选。

选择理由：用户最新说明此前较多使用 Spring Boot。使用其已有经验有利于理解、修改和解释后端代码。Spring Boot 承担 Web 接口、配置及依赖组织等基础设施；Agent 循环、上下文、工具协议、本地执行、错误处理和停止条件用 Java 自行编写。项目不引入 Spring AI 或其他 Agent 框架/SDK，避免核心逻辑被现成 AI 编排层替代。详见 [ADR-0001](../decisions/0001-frontend-backend-stack.md)。

Node.js 可作为 Vue 前端的开发和构建环境，但不增加 Node.js 业务后端；运行任务、调用模型、读写文件和执行命令均由 Java 后端负责。

### 通用基础设施建议

- 模型访问：一个 ProviderAdapter，先接通一个真实支持工具调用的模型。使用基础 HTTP 或厂商普通 API 客户端，不使用 Agent SDK；具体厂商、模型、API 方言待确认。
- 通信：HTTP 提交任务、审批、取消；SSE 推送运行事件。初版可以先不做模型逐 token 输出，但工具状态与命令日志须实时可见。
- 存储：每次运行的元数据 JSON 和追加式 JSONL 事件日志，先不引入数据库。历史回看读取日志，不重新执行命令。
- 测试：核心单元/集成测试，辅以 Web 端到端检查及真实模型任务评测；工具按最终技术栈选定。
- 部署：本地启动，默认仅监听回环地址；无需公网服务即可录视频。
- 实现阶段固定经过验证的运行时版本及依赖锁文件，不依赖未验证的“最新版本”。

## 3. 模块与依赖方向

### 前后端分离方式

- frontend/：Vue 3 页面、组件、请求封装和展示状态，独立安装依赖、启动和构建。
- backend/：HTTP/SSE 服务、自研 Agent 核心、本地执行器和运行存储，独立安装依赖、启动和测试。
- 两侧只通过明确的 HTTP/JSON 和 SSE 事件协议交互；即使语言相同、代码在同一仓库，也不直接导入对方业务实现。
- 前端不持有模型 API key，不承担本地命令执行；密钥和执行策略只在后端。
- 接口合同先写入文档；Java 后端 DTO 与 Vue 前端请求/事件数据结构按合同对应维护，不直接共享业务实现或敏感配置。
- 开发阶段可用前端开发服务器代理后端接口；后端仍校验请求来源和会话权限，不把“同源代理”当作授权。
- 前后端都在同一台电脑运行也属于前后端分离，无需购买服务器、拆成两个仓库或引入微服务。

### 运行关系

```text
Web UI
  | HTTP: submit / approve / cancel
  | SSE: events
API Server
  |
Agent Core ---- ProviderAdapter ---- 模型 API
  |
  +-- ContextManager
  +-- ToolRegistry + 参数校验
  +-- Policy / Approval
  +-- LocalExecutor ---- 任务工作区文件、子进程
  +-- RunStore / EventLog
```

前端显示后端事实，不自己决定工具是否成功。核心模块不依赖 Vue 或 HTTP，能在没有 Web 界面的测试中运行。初版同一工作区仅允许一个活动任务，工具串行执行，减少并发写文件和上下文顺序问题。

推荐代码组织（尚未创建）：

```text
  src/        # Vue 3 页面、组件、接口封装
  tests/      # 前端及浏览器检查

  src/main/java/  # Java 源码，项目包内按 core/tools/runtime/api 分层
  src/main/resources/  # Spring Boot 非敏感配置
  src/test/java/  # 核心、工具及 API 测试
examples/     # 无凭据、可重置的演示任务

```

## 4. 核心运行流程

1. 创建 run，记录任务、模型配置标识、项目版本及工作区状态；不记录密钥。
2. 组装系统规则、用户任务、历史消息及有限工具结果。
3. 调用模型；完整解析响应，按协议保留 assistant 工具调用信息与关联 ID。
4. 对每个工具调用验证名称、JSON 参数、路径、审批条件和运行预算。
5. 执行工具，记录结果、错误、耗时、退出码、文件变化等事实。
6. 按工具调用 ID 回填结果，再调用模型；工具失败也作为结果反馈，不伪装成功。
7. 模型结束、用户取消、预算达到上限、不可恢复错误等均有明确终止原因。

运行状态与验证结果分开：

- 运行状态示例：queued / model_pending / tool_running / awaiting_approval / finished / failed / cancelled / limit_reached。
- 验证状态示例：not_run / passed / failed / stale。
- 模型说完成只能表示本轮结束。测试通过必须来自真实执行结果，记录命令、退出码及对应文件版本；测试后再次修改相关内容，旧证据标记过期。
- 测试通过不代表任意需求被数学证明满足；总结须注明测试覆盖范围、未检查事项和人工检查结果。

初版不需要额外的规划模型或评审模型。可让同一模型输出简短计划，并根据工具结果调整；计划与解释不是内部思维过程的真实记录。

## 5. 最小工具集

| 工具 | 功能 | 必须处理的边界 |
| --- | --- | --- |
| list_files | 列出指定目录 | 深度、条目数、忽略目录 |
| read_file | 读取指定文件或行段 | 编码、大小、敏感文件、越界路径 |
| search_text | 按字符串搜索 | 文件数量、结果条数、输出截断 |
| write_file | 创建文件或明确授权的整体写入 | 覆盖确认、旧版本、大小、原子写入 |
| edit_file | 对已读内容做精确替换 | 目标必须唯一匹配，版本变化则拒绝并重读 |
| run_command | 在任务目录执行命令 | 审批、超时、取消、输出上限、退出码 |

可先使用精确字符串替换，避免首版投入复杂补丁解析器；前端 Diff 是根据实际执行前后内容计算的，不等于模型原本声称要修改的内容。

模型响应若采用流式传输，先组装完整的工具调用再解析执行；不能拿到半段 JSON 就执行。未知工具和参数错误应形成可处理的工具错误。

## 6. 上下文、错误与终止

### 上下文

- 不把整个仓库一次性塞给模型，通过搜索和分段读取获得信息。
- 对文件和命令输出设置上限，明确标记截断，并允许继续读取。
- 保留系统规则、用户目标、最近完整交互、近期错误和文件变化摘要。
- 裁剪必须以完整工具调用及其结果为单位，不能留下孤立 tool 消息或丢失必要关联 ID。
- 初版使用可解释的预算及裁剪规则；估算 token 时标明是估算，具体分词器按模型能力确定。超预算无法安全裁剪时明确停止。
- 自动语义摘要可作为后续增强，不将其视作无损压缩。

### 错误与停止

- API 限流或暂时网络错误：有限重试、退避，并显示等待状态；提示响应不确定时可能产生额外模型费用。
- 参数错误、找不到文件、编辑冲突：返回结构化错误供模型修正，不以 HTTP 服务崩溃处理。
- 命令非零退出：把退出码和输出回填模型，可继续修复。
- 已执行的写入或有副作用命令不因 API/SSE 断线自动重复。
- 最大模型轮次、工具调用次数、单命令时限、总运行时限、重复无进展检测，均可独立结束任务。
- 用户取消须传到模型请求与子进程；在支持的平台上验证进程树清理，不能只把界面改成“已停止”。
- 浏览器断线不等于任务取消。SSE 重连通过序号补发事件并去重，不能再触发一次工具执行。
- 第一版进程重启后将中断任务标记 interrupted，不承诺自动恢复有副作用的执行。

## 7. 安全边界

首版为可信用户、可信演示工程上的本地工具，不宣传为能安全运行任意恶意代码的沙箱。

- 默认 localhost；校验 Origin/Host、使用本地会话访问凭证，拒绝任意跨域请求。
- 文件工具仅操作登记的任务工作区；处理路径归一化、真实路径和符号链接，拒绝访问 .env、凭据目录、Agent 自身配置与运行记录。
- 任务目录与 Agent 源码/配置分开。仅复制无敏感信息的演示项目进行试跑。
- 读操作默认可自动进行；写入在用户明确授权的任务目录内操作并记录 Diff；命令首版逐次审批，不提供未经解释的全局放行。
- 命令采用程序和参数分离的调用方式，默认不启用 shell；这只能减少 shell 解释风险，不能限制程序本身的全部能力。
- 命令子进程只获得必要环境变量，不继承模型 API key；但这不代表其无法访问主机上其他文件。
- 展示和保存工具日志时遮盖已知凭据，不保存请求认证头；公开日志或截图前人工复核，不能声称通用脱敏可以识别所有秘密。
- 文件中的“忽略规则”“上传凭据”等文本作为不可信数据，不提升为系统权限。提示词规则不能替代执行器检查。
- cwd、路径校验、命令审批、程序白名单均不是操作系统级隔离；npm test 等命令仍会运行项目代码。
- 如扩展到不可信仓库，须单独设计容器隔离：最小挂载、非特权用户、资源限制、限制网络、不挂载 Docker socket 或宿主凭据，且做真实测试。作为后续阶段，不用“加 Docker”替代安全分析。

## 8. Web 界面设计

主界面包含：

- 顶栏：工作区、模型标识、当前状态、步骤/耗时、停止按钮。
- 左栏：任务历史、项目文件树。
- 中栏：用户任务、模型简短说明、按时间排列的工具卡片；卡片显示工具、主要参数、状态和耗时，可展开详情。
- 右栏：文件内容 / Diff / 命令输出 / 验证记录，使用标签页避免同时挤满屏幕。
- 输入区：任务输入、运行按钮；运行中避免重复提交，审批交互独立。

必做状态：等待模型、执行中、等待审批、错误、取消、结束；没有真实数据时显示空态，不以演示数据冒充结果。

视频模式优化字号、对比度和区域宽度，突出“工具动作 → 文件变化 → 验证证据”。模型解释显示为解释，测试状态来自后端真实记录。命令输出窗口不需要完整交互式终端模拟器。

受控示例项目的成果可在独立浏览器标签页展示。首版不将任意 Agent 生成代码嵌入 Agent 管理界面的同源环境。

## 9. 两类可追踪记录

### 开发决策记录

使用根目录 decisions/，只记录会影响边界、协议和行为的关键决策，不给每个样式细节写 ADR。填写格式见 [决策模板](../decisions/TEMPLATE.md)。

ADR 模板：

```text
编号、标题、日期
状态：proposed / accepted / superseded
对应需求
当时的问题与限制
考虑过的备选方案
最终选择及理由
放弃了什么、引入了什么风险
实现位置（实现后补）
验证用例和结果（实际运行后补）
关联提交（真实提交产生后补）
什么情况下重新考虑
```

拟议主题：

1. 单智能体串行循环及模块边界。
2. 模型协议与 ProviderAdapter。
3. 工具参数及文件编辑协议。
4. HTTP + SSE 与追加事件日志。
5. 本地审批和安全边界。
6. 上下文预算与完整消息裁剪。
7. 终止条件和“运行结束/验证通过”的区分。

变更已有决策时保留原记录，通过新 ADR 标记取代，不事后把旧决策改写成一直正确。AI 辅助情况如实记录，不编造用户已理解、已确认或手写全部实现。

### 运行事实记录

每次 run 记录：运行 ID、应用提交/脏工作区状态、模型标识、脱敏配置摘要、用户任务、事件序号、时间、工具调用 ID、参数摘要、审批、结果、文件变化、测试证据、终止原因和已知限制。

UI 和历史回看使用同一套事件事实。回看是历史展示，不是模型再次运行会产生相同结果的承诺，也不自动再次执行命令。

### 需求追踪

实际状态只维护在 [STATUS.md](STATUS.md) 的功能表中，关联决策、实现、测试及提交/运行证据，避免在多份文档重复维护完成清单。验证详情写入 [VERIFICATION.md](VERIFICATION.md)，阶段变化追加至 [DEVLOG.md](DEVLOG.md)。

## 10. AI 辅助开发协作方式

每个可验收小阶段按以下顺序推进：

1. 先说明本阶段的问题、建议方案、必要的备选与取舍；普通细节由 AI 推进，边界与架构大改需要用户确认。
2. 将重要选择写为 proposed ADR；用户确认后才改 accepted，不冒记用户认可。
3. 实现一条可演示的小流程，避免整仓库一次生成。
4. 执行针对风险的测试，并记录通过、失败、未验证项。
5. 做真实 Git 提交；一个提交代表一个可解释的改动，不伪造时间、不补造开发过程、不改写已推送历史。
6. 交付“本次改动、为什么、怎么看代码、怎么验证、限制、可提问点”，同步面试说明。
7. 用户用自己的话解释关键决策；有疑问先补理解，不以背诵答案替代掌握。

AI 可以承担核心实现，但无法仅凭文档保证用户理解。用户不必记住每个 UI 样式，却应能沿着一条真实运行记录定位核心调用链，并预测重要代码改动的后果。

## 11. 验证策略

三层证据不能混用：

1. 模拟模型的核心测试：验证状态机、调用 ID、异常、裁剪、停止、重复事件等确定性逻辑；不计作真实模型能力。
2. 临时工作区上的集成与 Web 测试：验证真实读写、命令、审批、Diff、刷新重连、取消和权限边界。
3. 真实模型任务：从同一干净起点独立执行，记录成功/失败、耗时、调用数和实际用量；未提供价格时不捏造费用。

至少覆盖：非法 JSON、未知工具、缺文件、唯一替换失败、路径逃逸/符号链接、命令非零退出/超时、模型 API 错误、重复无进展、步骤上限、取消、SSE 重连不重复执行、历史回看不执行工具、测试后修改导致验证过期。

真实任务建议三类：修复已有缺陷、新增跨文件小功能、从空目录创建带测试的小工具。保留预先制定的验收条件，不能只让 Agent 修改测试再宣布通过。

主视频可选“已有待办 Web 小应用的状态持久化缺陷 + 一项筛选功能”，但最终难度须根据真实成功率确定。准备无外部数据依赖、预装依赖、可独立重置的起始模板和独立验收测试。不要故意制造第一次测试失败；若自然发生，展示真实修复即可。

## 13. 视频与面试

建议视频结构（总长不超过 120 秒）：

- 0-15 秒：一句话说明项目、输入任务并展示初始问题。
- 15-70 秒：工具读取、修改、命令验证的真实过程，可剪辑加速。
- 70-95 秒：实际 Diff、验证结果、修复后的应用行为。
- 95-115 秒：核心架构和两项设计取舍。
- 115-120 秒：简短结束。

录像不能暴露 API key、请求认证头、真实 .env 或含凭据的终端历史。历史回放如用于演示应明确标注，不伪装成实时运行。最终视频只宣称实际存在和验证的能力。

面试材料围绕实际代码和 ADR，准备：

- 模型负责什么，程序负责什么？
- 工具为什么在本地执行？参数错误会怎样？
- 工具结果如何进入下一轮？
- 长上下文如何处理，信息会损失什么？
- 模型不停止或命令挂起怎么办？
- 浏览器断线和停止有什么区别？
- 为什么需要审批，为什么目录限制不是沙箱？
- 如何知道修改满足要求？测试没跑怎么办？
- 为什么选当前技术栈、SSE、单智能体和串行执行？
- 哪些部分由 AI 辅助实现，用户如何审核和验证？
- 已知失败案例与后续改进是什么？
