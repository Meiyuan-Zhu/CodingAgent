# ADR-0001：Vue 3 与 Java + Spring Boot 前后端分离

- 日期：2026-08-27
- 状态：accepted
- 实现状态：尚未实现

## 问题与约束

项目要求自行实现编程智能体核心。用户要求有 Web 界面、前后端分离，并能追踪与解释设计决策。技术选型需要兼顾项目完成、代码理解和面试说明，不能仅按 AI 生成代码的便利性选择。

## 已确认的信息

- 用户主要使用 Vue 3。
- 用户明确要求前后端分离。
- 用户最初表示后端接触较少，随后澄清此前较多使用 Spring Boot，并明确要求使用 Java + Spring Boot。后端选型以最新澄清为准。

## 考虑过的方案

1. React + TypeScript 前端：最初讨论建议；因用户熟悉 Vue 3 而撤回，未实现。
2. Vue 3 + Node.js/TypeScript/Fastify：曾基于前端语言经验提出，可减少语言切换；用户未接受，未实现。
3. Vue 3 + Java/Spring Boot：用户明确选择，与其已有项目经验相符。

## 决定

- 前端使用 Vue 3。
- 后端使用 Java + Spring Boot，不再增加 Node.js 业务后端。
- 同一仓库内分为 frontend/ 和 backend/，两侧独立依赖、启动、构建和测试。
- 前后端通过 HTTP/JSON 与 SSE 事件协议通信，不直接导入对方业务代码。
- Spring Boot 负责 Web 与配置等基础设施。Agent 循环、上下文管理、工具定义和执行、响应解析、终止条件及错误处理自行编写。
- 项目不引入 Spring AI 或其他 Agent 框架/SDK。普通 Web 框架的使用不替代题目要求的自研核心。
- 模型密钥及文件、命令执行权限留在后端；Node.js 仅可能参与 Vue 的开发和构建工具链。

## 理由

使用用户熟悉的 Vue 3 和 Spring Boot，降低阅读、维护与面试解释的成本。前后端边界与 Agent 核心边界分别明确，方便独立验证接口和核心行为。

## 代价与限制

- 前后端不是同一语言，Java DTO 与前端数据结构需要依据接口合同保持一致。
- Java 后端需要单独的构建与运行环境；具体版本和构建工具待环境检查后确定。
- 前端是否使用 TypeScript 尚未决定。
- 选型不代表已经完成实现，也不保证执行安全或任务成功；后续必须用真实测试验证。
